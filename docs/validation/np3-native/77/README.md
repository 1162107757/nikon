# NP3 空间处理与定向兼容：77 分阶段验证

2026-10-21，本页分阶段保留初始空间处理、Quick sharp 定向兼容和 v3 颜色修正的证据。各阶段使用同一个本地版本号 `cc.huevia` 77 / `0.13.9-beta`，但源代码与 APK 不同，不能混用哈希。最终冻结安装包和原生检查见阶段 C，发布结果单独记录。

## 阶段 A：初始空间处理候选（历史记录）

阶段 A 的 `dist/huevia-0.13.9-beta-debug.apk` 为 3,397,229 字节、SHA-256 `7fe08415ee23284cb015e46bc86ee39a032e5b90183dba29d3ca8af7bd232469`；v2/v3 签名通过。该摘要只属于此阶段，42 项原生报告保留在 `renderer-only/light/`，不作为后续 Quick sharp 定向兼容的安装包证据。

### 当时产品变化

- NP3 的锐化、中范围锐化、清晰度从只保留元数据改为真实三尺度近似。完整算法、局部限幅、alpha 权重、行缓存和 64 MiB 工作缓存限制见 `SpatialPreviewFilter`。
- 模板、照片预览和全尺寸图片共用 `renderPixels`；强度在完整空间结果之后混合，0 强度像素保持原样，嵌套强度保持精确整数语义。
- NP3 输出与缩略图缓存更新为 v2 模型；旧 NCP 模型和输出不变，旧 NP3 v1 效果仍可核对恢复原图关联。
- 当时 8 份未知字段和 1 份 Creative 基底仍明确拒绝，覆盖为 133／142；这项状态随后由阶段 B 的本地 NX 实证及定向规则更新。

## 阶段 B：NX Studio 实证与 Quick sharp 定向兼容

根任务已在真实 NX Studio **1.11.0.3000** 完成 Flexible Color Quick sharp -1／0／+1 的单变量导出，并将 ±1 分别与手动设置相同锐化／清晰度／中范围锐化的未指定 Quick 配方对照。独立审计确认各 NP3 对除名称和 `0x1400` 外其余记录一致。

同一 NEF、相同其它设置、原尺寸 sRGB 无压缩 TIFF16 的完整主图为 **6048×4024**；每份比较 **146,022,912 个原生 16 位 RGB 主像素字节**。+1 的四份重复／匹配导出全部逐字节相同；-1 的匹配两份也逐字节相同，同组 ICC 字节相同。这是完整原始 strip 审计，未经 8 位转换或区域采样。

| 定向状态 | 必须匹配的 field6／field7／field22 | 实际处理 |
| --- | --- | --- |
| `7f01`，Quick sharp -1 | `8004／8004／8004` | 三项均为 0，不重复叠加 Quick |
| `8101`，Quick sharp +1 | `8e04／8604／8c04` | 锐化 3.5／清晰度 1.5／中范围 3，只执行存储的三项值 |

原有 `ff01`／`8001` 参数行为保持；其它 Quick 编码、错误类型及不匹配 tuple 继续明确拒绝。Bluegrain 的 `0802` Creative 基底及传统控制仍未实现，因此覆盖是 **141 支持／1 明确拒绝**，不是 142／142 或所有 NP3 都支持。

定向规则的主机回归已完成：19,401 项合成检查；142 份固定原始配方得到 141 支持／1 拒绝、47 份自定义曲线、135 种不同输出、648,268 项 corpus 检查。检查包括 Quick 与手动等值 tuple 的整图结果一致、源字节保留、未知值和冲突组合拒绝。Native probe 已新增实际 corpus 的 ±1 解析、精确 tuple、不双算及 Creative 继续拒绝检查；最终产物及原生运行证据单独写入 `quick-sharp-verified/`，不覆盖阶段 A。

独立本地原始报告：[+1 完整 16 位对照](../../../../.research/np3-calibration/nx-1.11.0-DSC6182/evidence/independent-quicksharp-matched-plus16-20261021.json)、[-1 完整 16 位对照](../../../../.research/np3-calibration/nx-1.11.0-DSC6182/evidence/independent-quicksharp-matched-minus16-20261021.json)；主像素摘要、采集来源与范围详见[研究记录](../../../np3-compatibility-research-20261021.md#nx-studio-1110-的本地实证与定向兼容)。真实原片和图像仅保存在被忽略的研究目录，不随 App 打包或对外上传。

## 阶段 C：真实色彩对照与 v3 最终候选

最终候选为 `cc.huevia` 77 / `0.13.9-beta`，3,438,189 字节，SHA-256 `88d284ffadb92c8ce15c1e5833f00c9fb25a8608b8071557c6464f4c7e6d5ec5`，v2/v3 签名通过，沿用证书。与阶段 A、B 的同版本号本地包分开记录，不能混用旧原生报告。

v3 修正两项近似：对比度使用原始已编码 RGB 近似亮度产生的三通道共同 sine 偏移；Color Blender 亮度幅度乘原始输入 HSL 饱和度。它降低旧模型的严重高光剪裁与近灰区域过度亮度调整。曲线采样处理未改，但包含 Blender brightness 的曲线配方最终输出会变。新模型缓存隔离 v1/v2；精确旧原图关联恢复保留两种历史身份，已有旧效果字节不改。

真实 NX Studio 1.11.0 TIFF16 对照覆盖两张独立 NEF；第二张在候选冻结后才用于预测，未参与拟合，两张仍属于同一室内环境。各图完整处理 6048×4024 像素，误差统计使用同一组 61,206 格点。第二张完整 SunsetFilm 配方的 RGB MAE 从 19.697 降到 4.792／255，ΔE00 中位数从 6.379 降到 2.241，P95 从 9.292 降到 4.752。去除空间参数的颜色控制仍存在明显残差，NX 与 App 的空间联动明度响应也不一致，完整配方的部分改善可能包含误差抵消；不得据此声明完整校准通过。详见[机制与实际数据](../../../np3-rendering.md)、[来源和边界](../../../np3-compatibility-research-20261021.md)。

最终产品源码与冻结候选除注释／模型名外数值行为一致；第二张完整 24,337,152 像素的全部已解码 RGB 逐字节相同。主机回归：24,829 项 NP3 合成、648,268 项 corpus 检查（141 支持／1 拒绝）、34,780 项强度／草稿、609 项批处理、82 项原图关联，以及 16 组空间引擎检查通过。旧 v1/v2 恢复检查确认历史图片与完成记录不改，v3 使用独立输出键。

[最终原生报告](colour-v3-verified/light/report.json) **58 项通过**，包含新增 8 项 v3 颜色／alpha 行为、实际 Android JPEG/sRGB/EXIF、空间处理、完整效果后强度混合和取消。范围为 `renderer-only / light`，本轮未跑原生 full batch／MediaStore／UI；批处理依据上述主机回归，不将旧原生完整流程算作本版通过。 [构建／签名／来源绑定](colour-v3-verified/build-verification.json)固定 174 个来源哈希并在结束后复核，自建隔离模拟器已关闭。

## 尚未完成的实际目标与证据边界

最终包已于 2026-10-22 发布为 `0.13.9-beta`。双域公网文件和更新元数据均核验通过，详见[发布验收](../../huevia-release-77-20261021/README.md)。发布成功不改变下述色彩与空间复现范围。

当前仍是自定义近似模型，**全色彩校准尚未通过**，Creative 基底仍不支持。阶段 B 证明已验证 Quick 状态不应在所存三项空间值之外重复施加效果，不能证明 App 的颜色公式或三尺度滤波与 NX 相同。其它 Quick 档位、更多 NX 版本／原片、缩放尺度及组合色彩仍需专门对照。工具测试与手工合成配方不作为官方基准。

阶段 A 结束时，NX Studio 尚处于由用户完成的登录及准备 NEF 阶段；随后已经取得本地原片并完成阶段 B，不能把那时“尚无基准”的描述当成当前状态。任务没有操作登录控件或凭据。基准工具要求颜色／空间拟合使用逐字段验证的零调整 A，避免 NX 默认锐化与目标配方重复叠加；其独立工具测试和 JVM 桥接结果保持自身范围，不替代实际 NX 色彩验收。

完整步骤见[校准说明](../../../np3-calibration.md)，历史线索和新增实证见[研究记录](../../../np3-compatibility-research-20261021.md)。Android 验证使用合成图片与研究配方，没有连接真实相机或实体手机；NX 阶段仅在本地处理用户授权原片。
