# Z6II 长下载与断线恢复（73 / 0.13.5-beta）

用户现场反馈：Z6II 从相机下载照片时黑屏，时间较长会断开，唤醒后原任务不能继续；同一卡存在 RAW，但从照片导出时提示找不到 NEF。本轮只修复可在代码与测试中确认的缺陷，并改善 RAW 自动匹配失败后的选择路径，不将模拟结果当作用户机身实测。

## 已确认的两个连接缺陷

- 原图虽然使用 600 秒总期限，底层单次 socket 读取仍在 15 秒无数据时直接终结连接。现在仅原图接收使用同一事务共享的 90 秒无正字节进展期限和 600 秒绝对期限；短暂读取超时保留半包偏移继续，不重发请求。元数据查询和预设读写的超时策略保持原有语义，事件通道原有独立 ping 响应保持。
- 网络失联会让 Controller 旧 generation 的下载回调失效，但 UI 原先仍依赖该回调结束 busy。现在失联状态通知直接结束旧传输状态；未完成清单由运行时 Controller 持有，供用户重连后继续。

## 恢复范围

完整批次在开始时捕获可信非零相机 GUID、厂商／型号、句柄与完整对象描述。完成原图提交或可靠复用后立即移出清单，不依赖旧界面回调。重新连接后，用户明确点击继续，先核对同一可信相机、当前库存句柄和完整元数据，再绑定新 session。

不同相机、无可信身份、句柄消失、对象信息变化或存在未完成核对时，均不猜测替代文件。显式取消、断开和实际账号身份变化清除恢复意图；自动网络／服务异常保留意图。相机与手机上的完整照片不因清单清理而删除。

恢复清单只保存在本次进程内存中。已完整保存的原图可以验证后跳过；当前未完成照片会清除半成品并重新下载整张，未实现跨连接按字节断点续传。

## RAW 现场问题的边界

当前自动 RAW 导出会先核对相机来源、完整库存和 JPEG／NEF 的唯一对应关系。配对阶段拒绝，不代表已证实存储卡没有 RAW；这与下载完毕后的 NEF 结构检查是不同阶段。实际 NEF 文件保持按原字节下载和独立验证，不能用放宽配对或把 JPEG 改扩展名替代。

自动配对失败现在通过专用 `SelectionRequiredException` 与回调交给界面：提示本次实际读取的对象／NEF 数量，区分「连接未列出 NEF」和「存在 NEF 但不能唯一对应 JPG」。健康尼康连接下，单张 JPG／旧本地照片的匹配失败提供「选择NEF原文件」，打开已有相机 RAW 列表，由用户明确选择；直接 NEF 下载或结构验证失败仍走原文件重试，不偷偷替换文件。

RAW 主机回归 126 项通过，包括自动配对拒绝后明确选取 NEF 的原字节下载、库存计数、歧义／无可信身份拒绝、旧本地 JPG 路径与直接 NEF 错误重试。没有取得用户 Z6II 实际库存及 NEF 样本，因此不能据此声称现场 RAW 库存问题已经证实解决。

## 相机待机设置对照

可在 Z6II 的「自定义设定菜单 → c3 电源关闭延迟 → 待机定时器」延长时长，或临时设为「无限」后进行同批照片对照。官方说明 c3 管理显示／待机时长，[节能说明](https://onlinemanual.nikonimglib.com/z7II_z6II/zh-cn/09_menu_guide_06_34.html)也明确存在「无限」选项；单独关闭节能仍可能在待机前变暗。[c3 说明](https://onlinemanual.nikonimglib.com/z7II_z6II/zh-cn/09_menu_guide_05_c03.html)

尼康的 [SnapBridge 下载排障](https://nikonimglib.com/snbr/onlinehelp/cn/auto_download_49.html)建议下载异常时延长过短的待机时间，但这不是本 App 现场故障的根因证明。黑屏也不能单独证明 Wi-Fi 已关闭；已断开的 PTP 会话不会因为半按快门而自动恢复。
