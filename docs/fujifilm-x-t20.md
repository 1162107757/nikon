# 富士 X-T20 照片下载（实验）

0.12.0-beta（62）新增富士 X-T20 的独立 Wi-Fi JPEG 传图适配；0.12.1-beta（63）修复热点地址选择；0.12.2-beta（64）补齐单字节属性解析；0.12.3-beta（65）优化分批读取和预览排队；0.12.4-beta（66）兼容 JPEG 主图结束后的附加数据；0.12.5-beta（67）调整原图读取的分块与等待方式。用户真机已确认连接、列表和预览快速可用，原图导出出现读取超时，尚未通过完整下载验收。

## 使用

1. 先在 X-T20 拍摄照片，再打开拍摄设置或回放菜单中的“无线通信”。
2. 在 Huevia 的“设置 → Wi-Fi 无线连接 → 相机类型”选择“富士 X-T20（实验）”。
3. 保持“自动识别相机地址”勾选，端口为 `55740`。点击“连接相机”，按提示选择相机热点；若热点没有密码，明确选择无密码网络。Android 10 及以上会在系统连接完成后，读取所选热点本次实际提供的 IPv4 网关。
4. 在相机上确认新的手机连接。关闭 Camera Remote 等其他占用相机的应用。
5. 进入相机照片页浏览和下载 JPEG。下载后可沿用现有的系统相册保存及手机套预设功能。

尼康与富士分别保存 IP、端口及未完成的编辑。切换类型不会把富士的端口带入尼康预设导入。重连需用户主动操作。

相机热点的地址以每次连接的实际网关为准，不能写死 `192.168.0.1`。手机 WLAN 详情中“IPv4 地址”表示手机自己，例如 `192.168.186.2`，不能当作相机地址。关闭自动识别后需要填写“网关／路由器”地址；旧版 Android 没有指定热点请求时同样需手动确认。

系统回报网关可能稍晚于热点已连接通知，应用会在相机工作队列短暂等待。没有有效网关时明确失败，不访问保存的旧 IP、不扫描网段，也不通过手机 IP 猜测 `.1`。网关读取、三个相机通道及手动自连拦截始终使用同一个系统授权网络。

连接相机 Wi-Fi 后，还需在相机出现手机名称或连接请求时按 OK 允许访问。若已经失败，请重新进入相机“无线通信”，再从 App 发起连接。按 OK 后出现“富士属性长度无效”属于旧版解析兼容问题，无需继续修改 IP；64 版已支持 1、2、4 字节数值属性。异常长度会显示属性编号，命令与辅助通道的网络错误会显示实际失败端口。

## 能力与限制

| 功能 | 本版状态 |
| --- | --- |
| Wi-Fi JPEG 列表、缩略图和下载 | 真机已确认连接、列表及预览；原图导出超时排查中 |
| 系统相册保存、下载后的手机套预设 | 复用现有 JPEG 流程；本轮未做富士真图验收 |
| 按机身快门后持续自动传图的照片直播 | 未开放 |
| 遥控取景、遥控快门 | 未提供 |
| RAF、视频、USB 照片下载 | 本次未加入 |
| 向富士相机写入 NCP / NP3 | 不支持；NCP / NP3 为尼康格式 |

富士官方 X-T20 指南明确支持通过 Camera Remote 浏览和导入照片，以及遥控取景拍摄。但遥控取景与 Huevia 现有的照片直播是不同流程。官方软件兼容表中，X-T20 无联机拍摄支持，Tether App 仅支持设置备份恢复。不能将无线传图或遥控取景推断为按机身快门持续传图。

当前拒绝在富士会话上新建或续接直播，也拒绝移交尼康预设写入；拒绝不会停止健康的富士下载会话。已有直播项目仍可离线浏览。

## JPG 与 RAW 导出入口

只拍摄 JPG 时没有对应的相机 RAW 原文件，JPG 原图也不等于 RAW。当前富士会话仅支持 JPG 传输，不能使用尼康 NEF 的 RAW 扫描／导出流程；即便富士拍摄了 RAF，也不代表当前适配已支持下载 RAF。

68 版起，富士会话的单张及批量导出直接使用 JPG，不提供 NEF 导出选项。底层同时拒绝误调用 RAW 列表、RAW 配对及 RAW 下载，拒绝前不发送相机命令，也不关闭健康的 JPG 连接。本机已保存的尼康 NEF 仍可离线浏览和保存。

`PTP StoreNotAvailable (0x2013)` 表示相机存储暂不可用，不能仅凭这个响应判断“未找到 RAW”。新版会用中文说明存储问题，并提醒只保存 JPG 时选择 JPG 导出；只有完整清点可读存储并核对来源后，才会报告未找到对应 NEF。

## 列表速度与预览失败

65 版将富士列表从每批 24 张改为 6 张，统一在每批开始和结束时切换文件大小模式，先请求这一批预览，再继续读取列表。协议夹具中，同样 24 张元数据从 120 条指令减少为 28 条；实际界面每批 6 张需要 10 条，减少首批预览前的等待。相机请求仍顺序执行，不在同一个协议通道上并发发送。

当前会话缓存最多 48 张、合计 8 MiB 的有效 JPEG 缩略图。缓存返回副本；照片描述变化、照片数量变化及描述淘汰会使相关缓存失效。原图下载前后仍重新读取照片描述，不用缓存信息代替完整性核对。

列表区分加载中和预览不可用。若单张照片显示“预览失败，轻点查看原因”，点击会展示实际协议、JPEG 完整性或解码错误，之后可选择“重试预览”。旧版只显示“暂无预览，轻点重试”，未取得错误详情，当前不能确定用户的预览失败根因。不会为了填充预览自动下载整张原图。

用户随后提供了具体错误：`GetThumb / 0x100A，收到 21314 字节，缺少 JPEG 结束标记`。旧检查要求响应最后两个字节必须是 `FF D9`，会把主图已完整结束、后面仍有附加数据的响应也判为截断。66 版仅在富士 GetThumb 读取后，按 JPEG 段长度跳过 APP／EXIF 等段，并识别扫描中的转义、重启标记和多次扫描，定位主图真实的 EOI；存在完整主图时保留至 EOI，裁掉后续字节，再进入网格、单张预览和缓存。不搜索 EXIF 内嵌 JPEG 冒充主图，不追加缺失的 EOI，未识别的响应保留原有检查；原图读取及保存检查不变。

截图没有提供这 21314 字节原始内容，因此附加数据属于本次修复覆盖的兼容情况，尚不能断言真机响应一定包含完整主图。协议测试使用同样总长度的合成响应复现旧判断，并用真实可解码的基线／渐进 JPEG 验证处理结果，实际相机仍需复测。

用户随后确认 66 版连接和查看速度正常，预览兼容已获真机反馈。导出 `DSCF9186.JPG` 则报 `Read timed out`；该旧提示没有携带命令或阶段，不能确定相机是在照片信息、首个分块还是后续响应处停顿。67 版把原图分块从 1 MiB 改为 256 KiB；原图分块等待首字节最多 90 秒，收到数据后使用 30 秒连续无数据时限，每个分块事务最多 180 秒。其他元数据和预览事务仍保留 30 秒总上限。

socket 以短等待轮询，超时轮询保留已接收的帧位置，不重发未确认的命令。真正超过停顿／总时限时关闭所有通道，原图仍须完整接收及核对才可保存。超时会显示具体命令、属性或分块偏移、包头／包内容阶段及本次响应收到的字节数，重试前需重新连接相机。

若传输文件尺寸较小，请检查相机“连接设置 → 无线设置 → 调手机图尺寸”，关闭后重新连接并下载。相机默认可能提供缩小后的手机副本，应用不重新压缩相机原图数据；大小应结合下载照片像素尺寸判断。

## 实现边界

- 富士采用独立的 TCP / PTP 容器握手；不直接复用尼康 PTP/IP 握手。
- 相机必须实际返回 `X-T20` 名称，才继续会话与图库协商；其他或缺失型号会被拒绝。
- 命令端口及固定的 `55741 / 55742` 辅助通道，始终绑定同一个系统授权的相机 Wi-Fi；网络丢失后不能转向其他网络。
- 按富士协议协商遥控通道并立即退出到图库，未发送快门或删除命令。属性设置只用于协议版本、图库模式及正确文件大小。
- 富士相册接口将事件返回的照片数量映射为索引和一个虚拟存储空间。设备能力数据是本地适配层的数据集，型号来自实际握手；不会冒充相机返回的标准 GetDeviceInfo。
- 原图按最多 256 KiB 分块接收。事务编号、包大小、分块长度、声明文件大小及现有 JPEG 完整性检查通过后才确认保存；取消会关闭全部通道。
- 不将 RAF 标为 NEF，不把缩略图当作原图。实际机身固件差异、原图分辨率、速度、长时间连接及 Android 后台行为仍待实测。

## 验证

协议合成测试覆盖富士握手、型号不匹配、图库模式顺序、虚拟目录、元数据、分块下载、保活、错误事务、超大包、截断和中途取消。相册能力测试覆盖富士 JPEG 下载、直播及尼康预设移交拒绝、Nikon 大缩略图隔离。生产 Wi-Fi 连接器测试覆盖三个端口和网络丢失。偏好配置测试覆盖原尼康迁移、富士默认值和两种机型的地址隔离。

新增网关测试覆盖实际网关与手机 IP 不同、相机网段变化、非 `.1` 网关、另一个默认 Wi-Fi、网关延迟／缺失、网络丢失与取消；错误地址不会触发 socket。用户截图证明旧版尝试了固定错误地址，或把手机自身 IP 填成目标，均在 TCP 连接阶段被拒绝；这不是富士握手已成功的证据。

64 版使用混合 1／2／4 字节属性夹具复现并修复旧提示；0／3／5 字节异常输入继续失败并关闭通道。命令、事件、预览通道分别拒绝连接时，验证实际端口及已有通道关闭。

65 版补充每批状态恢复、批次取消、24 张元数据指令数量、缩略图副本隔离、缓存淘汰及描述／数量变化失效测试。66 版增加可解码 JPEG、尾部数据、21314 字节响应、APP 内嵌主图误匹配、逐字节截断、无效段长度、多扫描、转义及重启标记检查，并验证规范化后的缩略图缓存及原图传输字节不变。67 版用虚拟时钟验证 45 秒准备延迟、单块传输超过 30 秒仍有持续数据、首字节／中途停顿／180 秒总时限、实际失败命令诊断、短超时不重复发送和等待中的取消。协议合成测试不能替代 X-T20 真实 JPEG 下载测试。本轮没有发布版本或自动安装实体手机。具体构建摘要与测试范围见 `dist/nikon-usb-0.12.5-beta-VALIDATION.txt`；旧版验证记录继续保留。
