# 手机端 NP3 调色

手机端读取预设中的参数，对照片已经解码的 RGB 像素进行近似调色。原始 NP3 与照片保持原样，处理结果另存。这个过程发生在手机上，不要求拍摄机型支持 NP3，也不会让老机型获得在机内加载 Flexible Color 的能力。

NP3 是容器格式，不能仅凭扩展名断言滤镜可用。当前只处理经过结构和参数检查的 NP3 `0310` Flexible Color 子集；Creative Picture Control、尚未解释的非中性字段、未知版本及损坏文件会返回具体原因。

## 支持范围与效果边界

| 内容 | 手机端处理 |
| --- | --- |
| 32 个基础 TLV 记录、名称、可选 UTF-8 备注 | 校验顺序、长度、版本及值域，读取时复制所需数据 |
| 自定义曲线 | 读取 257 个大端 16 位采样，按输入位置线性插值；保留合法的非单调段 |
| 对比度、高光、阴影、白阶、黑阶、饱和度 | 作为明确标注的应用近似映射参与调色；自定义曲线启用时覆盖前五项 |
| Color Blender | 读取红、橙、黄、绿、青、蓝、紫、洋红八组色相、色度、亮度参数，近似调整对应颜色 |
| Color Grading | 读取高光、中间调、阴影的色相、色度、亮度，以及混合度和平衡，近似执行分区调色 |
| 锐化、中等范围锐化、清晰度 | 解析并保留元数据；此版不执行空间滤波 |
| 相机基础色彩、RAW 显影、降噪、镜头校正、白平衡 | 不由这个逐像素调色模型复现 |

当前模型版本为 `np3-0310-encoded-hsl-zones-v1`。模型先在已编码的显示 RGB 上逐通道处理曲线；无自定义曲线时，用 `2^(contrast/100)` 及平滑端点权重近似基础色调。随后在 HSL 空间调整饱和度，并在八个色相锚点之间插值执行 Color Blender；Color Grading 使用亮度上的高斯权重混合三个分区。分区偏移预计算为 1025 个查表采样，再按亮度线性插值，避免逐像素计算指数函数。色相幅度、亮度幅度、权重形状与处理顺序均是应用自己的假设，具体公式记录在 `Np3PreviewProfile` 类注释中。

对 JPEG 再套用预设，会叠加在相机已经处理过的颜色、白平衡和曲线上；压缩、剪裁的高光或丢失的暗部不能恢复。对于非 sRGB、HDR 或广色域照片，本模型也没有独立的色彩管理或 HDR 显影流程。因此即使所有参数均成功解析，结果也不能视为尼康机内直出或 NX Studio 的等效输出。

相同参数和输入像素的输出具有确定性，alpha 保持不变；输入数组及文件字节不会被修改。缩略图和批量处理共用同一调色模型。模型版本参与缓存标识，以便以后校准算法时刷新结果。

## 照片流程与兼容性

本地导入或在线下载的受支持配方可在详情查看模板效果、按住对比原图，也可在相册的“选择预设”或直播项目默认预设中选择。处理范围沿用现有流程：应用相册中已完成的完整 JPEG 原图；不是 RAW 显影或任意系统图库导入。效果按完整尺寸转为 8 位 sRGB JPEG 95 另存，内存不足时明确失败，不静默缩小原图。

旧 NCP 保持原模型版本和输出键；NP3 使用独立模型键，保存预设 SHA、原图 SHA 和模型身份对应的原图关联。若输出和完成记录已提交但关联尚未保存，恢复仅尝试已登记的旧 NCP 与当前 NP3 模型，以完整身份核对原图；不根据相邻文件或画面猜测。重新套用会追溯原图，不对旧效果图叠加同一配方。

最终 0.11.0-beta / versionCode 57 在隔离 Android 17 模拟器上通过浅色、深色各 60 项原生检查，覆盖真实 NP3、本地模板、1800×1200 JPEG 编解码与 EXIF、效果复用、原图关联、真实 MediaStore 提交及输出字节一致。报告见 [浅色](validation/np3-native/light/report.json)与 [深色](validation/np3-native/dark/report.json)。未验证物理手机性能、24MP 长时间批处理或与 NX Studio 的颜色精度；现有相机导入流程不因手机可渲染而新增 NP3 写入能力。

## 真实文件验证

独立 runner：

```powershell
.\tests\run-np3.ps1
# 如需指定 JDK：
.\tests\run-np3.ps1 -JdkHome 'D:\dev\Java\jdk-17.0.19'
```

runner 先编译并运行独立 JVM 合成测试。如果本地已有 `dist/nikon-cloud-recipes-20261018/nikon-cloud-recipes-142.zip`，还会直接只读验证其中全部 142 份 NP3；不下载、不解压、不复制第三方预设进源码目录。缺少 ZIP 时明确显示 corpus 被跳过，合成测试仍运行。可用 `-CorpusZip` 指定相同已知样本包的位置。

样本包身份由 `cloud-only-inventory.json` 及 ZIP 的 SHA-256 固定为 `7a1cf3cd719ed9ec69dae4936625afb1fc3cc1871bc6d61f46c27903a32a087c`。其中 95 份只有基础记录、47 份附带自定义曲线。预期为 **133 份可调色、9 份明确拒绝**；全部拒绝或未知的新增拒绝均会使测试失败。

可调色文件逐份检查 4096 个覆盖 RGB 空间与全部 alpha 值的像素：必须产生可见变化、保留 alpha、重复输出一致、单像素与数组处理一致、不修改输入、不共享返回数组或调用方文件数据，并检查曲线结果范围。测试还要求至少 100 种不同输出，当前 133 份支持配方得到 127 种输出。这些检查证明输入输出与覆盖范围，不证明尼康色彩还原精度。

已知的 9 份拒绝样本固定到具体文件：

| 文件（均位于 Nikon Creators） | 原因 |
| --- | --- |
| `Bluegrain_jyota.NP3` | 使用 `0x0802` Creative 基底，本模型仅处理 `0x0020` Flexible Color 基底 |
| `24Look_24Frames.NP3` | 尚未解释的 `0x1400` 字段为 `0x7f01` |
| `BlueHour_Luna.NP3` | `0x1400` 字段为 `0x8101` |
| `GoldenHourGlow_DAnn.NP3` | `0x1400` 字段为 `0x8101` |
| `HKReminisce_Hiuman.NP3` | `0x1400` 字段为 `0x8101` |
| `PainterlyLight_DAnn.NP3` | `0x1400` 字段为 `0x8101` |
| `Pastelpink_Yuki.NP3` | `0x1400` 字段为 `0x8101` |
| `SunsetFilm_JKBoy.NP3` | `0x1400` 字段为 `0x8101` |
| `WarmDimLight_Luna.NP3` | `0x1400` 字段为 `0x8101` |

`0x1400` 的 `0x8001` 和未指定值 `0xff01` 可被接收；不能把另外两个值直接猜作某个已知调色参数。确定语义后，应新增单变量样本和对应测试，再扩大支持范围。

## 格式依据与后续校准

参数位置、编码和可选曲线结构参考 [ssssota 的 NP3 读写源码](https://github.com/ssssota/nikon-flexible-color-picture-control/tree/main/src)，其工作是读取与写入格式，并没有提供可直接复刻的尼康像素渲染器。独立项目的[格式研究说明](https://github.com/noobsaibot666/nikon_cps_generator-converter/blob/main/docs/NP3_FORMAT.md)同样列出尚未解释的字段；当前实现不会忽略它们的未知非中性值。

功能含义参考 [Nikon NX Studio Flexible Color 帮助](https://nikonimglib.com/nxstdo/onlinehelp/en/the_picture_controls_flexible_color_23.html)。该帮助说明了曲线与基础色调参数的覆盖关系、Color Blender 的八组颜色，以及 Color Grading 的分区、混合与平衡；它不是公开的渲染算法规范。

后续需要使用同一批原始文件和配方，在 NX Studio 固定白平衡、色彩空间、曝光及导出选项，生成基准图。逐项对比中性灰阶、肤色、饱和色、暗部与高光，再校准映射函数、颜色权重和处理顺序。校准完成前，界面与导出说明应持续使用“近似调色”，不宣称与官方处理一致。
