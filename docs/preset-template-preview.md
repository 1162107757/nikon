# 预设模板模拟 · 0.5.2-beta

0.11.1-beta 将相同模板模型扩展到未下载在线预设：列表只处理可见卡片，滚动暂停新处理，双线程与有界队列限制并发，详情优先。独立配方缓存先校验长度、SHA-256 和容器格式，不添加本地预设；模拟缓存同时区分配方、模型、模板及图像尺寸。离开页面取消旧任务，更换模板和页面结果均通过 epoch 检查。加载、失败和不支持均明确展示，实拍参考单独保留；在线详情也能按住“原图”比较。以下未下载样片优先规则是旧版本行为。

0.11.0-beta 新增 NP3 0310 Flexible Color 手机近似模型，共用模板、原图对比和选择器；详情中的“手机色调映射”只表示亮度部分，不代表完整混色和分区调色。已验证 133 份配方可渲染，9 份明确拒绝。以下 NCP 章节继续描述旧模型，新增算法和限制见 [NP3 调色说明](np3-rendering.md)。

已下载预设的主图（含在线列表的已下载项）把受支持 NCP 的可解析色调参数应用到统一模板，标记为“模板模拟”。这是一种手机近似预览，用来比较部分色调变化；不是相机实拍，也不证明兼容登记后的拍摄效果。原 NCP 和关联样片不改写，配套实拍仍可单独查看。未下载在线预设优先展示发布者提供的样片；0.9.6-beta 起，缺图或样片加载失败时显示当前模板原图，标记“模板示意”，明确尚未应用预设，下载后才生成模拟。模拟失败可点按查看原因并重试。

模板示意在 image worker 读取 `originalTemplate()`，默认使用内置图，也沿用用户在设置中选择的模板。缓存键为独立的 `template:<version>`，不覆盖样片 URL 或对比原图的缓存。模板版本、页面 epoch 和视图 tag 都匹配后才更新画面；样片失败仍可在详情中重新加载。后台可不上传预览图直接发布，目录的空 `previewUrl` 会使用此回退，不生成虚构样片。

## 详情中的只读色调曲线

0.5.2-beta 在本地已下载预设的详情照片与名称区域下方增加原生色调曲线卡。蓝色实线连接原 NCP 的 257 个实际归一化采样，直接调用同一 `NcpPreviewProfile.mapTone(i / 256.0)`，不做平滑；虚线与图例表示线性参考。横轴输入、纵轴输出均以 0–255 标注，曲线卡基础高 188dp 并随系统字号增长。它只展示色调表，不包括 HSV 近似、尼康基底或相机完整渲染，也不提供编辑。

原文件在 image worker 通过 `PresetLibrary.readNcp()` 核对大小、SHA-256 和结构后严格解析，profile 以 NCP 内容哈希缓存到最多 8 项的 LRU。同一预设的待处理请求复用后台任务，并保留最新页面目标；页面 epoch 排除旧结果。加载中与解析失败分别显示真实文字，失败可点按重试，不为不支持的文件生成替代曲线。未下载在线预设不显示这张卡。辅助描述包含 257 点及三个代表输出；辅助功能路径尚未通过 TalkBack 实测。

## 详情中对比模板原图

0.5.1-beta 在已下载预设的详情主图右下角加入“按住看原图”，0.5.2-beta 将可见文字缩短为“原图”，完整操作说明仍保留在辅助描述中。触摸按下显示未应用预设的模板原图，松开立即恢复效果；两态使用同一 `CENTER_CROP` 视图，保持裁切不变，角标显示“模板原图 / 模板模拟”。按钮高 48dp，距右侧、底部各 12dp；原图和效果均就绪后才启用，准备中或失败时显示实际状态。

移出按钮、取消、增加触点或页面失焦、暂停、隐藏、卸载都会恢复效果；移回按钮不会重新显示原图。键盘 Enter、空格或方向键中心，以及辅助功能点击使用独立的点击切换：一次看原图，再次恢复。辅助功能状态与说明已实现，TalkBack 操作尚未实测。详情原先的外部原图入口由此替代；“设置 → 预览模板”仍可查看当前模板原图。

原图在进入详情时异步准备，按模板版本缓存到既有图像 LRU；模板版本与页面 epoch 阻止旧任务更新当前页面。触摸按下只切换已解码 bitmap，不读取或解码图片，也不播放过渡动画。

## 支持范围

`NcpPreviewProfile.fromNcp()` 使用独立的只读预览校验：仅 638 字节 NCP 0100，36 字节预设记录、578 字节曲线和终止记录；支持既有 Standard / Neutral / Vivid / Portrait / Landscape 彩色基底，锐化 0–9、饱和度与色相 -3–3、自定义曲线模式及已验证的元数据组合。未知版本、记录、Auto、单色、越界采样等明确拒绝，不以随机滤镜或改扩展名代替解析。

2026-10-18 修复了 Bluesky 无法生成模拟的问题。原预览错误复用相机写入转换器，把偏移 38 的修改状态限定为 `0x00`；公开在线库的 Bluesky 为 `0x02`，因此在真正读取模板前已经被拒绝。[原始 NCP 解析工具](https://github.com/simeonpilgrim/nikon-firmware-tools/blob/main/nfiles/dumpncp.pl) 将该字段解释为修改状态，不是曲线或颜色参数。只读预览现在直接读取文件中已有的曲线、饱和度及色相，不受这一修改状态限制；其它既有验证边界保持，手机近似模型没有改变。`NcpPictureControlConverter` 没有放宽，相机兼容导入仍会拒绝未经验证的修改状态，不根据手机可预览就推断可安全写入相机。

真实公开样本为 638 字节，SHA-256 `2bab29630bbc537025c5daf68f6b7ab90a866e5c97e6dc7430dd4fe4ad547eb6`；解析为 Vivid、锐化 5（只展示元数据）、饱和度 +1、色相 0，曲线原始采样的输入 0 / 128 / 256 对应 0 / 15651 / 32767。测试原文件仅保留在被忽略的 `.tooling` 目录，不改写原预设。针对修改状态 0 / 1 / 2 / 255 的回归核对同一曲线和像素结果、输入不变以及相机转换器仍拒绝非零状态；本次预览检查 2167 项、相机兼容转换检查 77 项通过。主图仍显示“模板模拟”，不宣称尼康相机色彩等效。

曲线记录从文件偏移 56 开始，记录内偏移 64 处为 **257 个 big-endian 16 位采样**，每项范围 0–32767；输入索引为 0–256。[开发者的原始曲线研究](https://github.com/horshack-dpreview/NikonPictureControlsDev) 将它描述为作用于 post-sRGB 数据的亮度 UDC，并指出相机基底 TRC 并未存入 NCP。[尼康自定义曲线帮助](https://nikonimglib.com/npcu/onlinehelp/en/pc010000.html) 说明曲线与输入、输出及 Gamma 调整的关系；它没有给出本 App 所需的完整相机渲染管线。这些参考不构成本 App 颜色等效的证明。

## 0.10.2 的 NCP 修改状态修正

上面的“转换器仍拒绝非零状态”属于此前仅修复预览的历史行为。0.10.2-beta / versionCode 56 在相机兼容转换中识别偏移 38 的 `0 / 1 / 2` 三个已知修改状态；这个字段只描述预设文件状态，不进入相机写入参数。偏移 39 仍须为 `0xFF`，未知状态（包括 3、255）、结构、名称、颜色参数及曲线范围的原有检查均保留。原 NCP 不改写。

实际 Bluesky 的状态为 2。将同一输入的该字段分别设为 0、1、2，得到相同的 614 字节相机参数；源文件哈希不变。98 项转换与 2168 项预览检查通过。这里只验证文件解析及兼容参数一致，不证明相机原生渲染等效，也没有以这次修复为由重复写入真实相机。

## App 近似模型

模型版本为 `encoded-rgb-tone-hsv-v1`：

1. 将已编码显示 RGB 的各通道归一化，以 `通道 / 255 × 256` 查曲线，两个采样间线性插值，输出除以 32767 后量化至 8 位。
2. 用 HSV 做 App 自定的颜色近似：饱和度乘 `1 + step / 6`，上限 1；色相旋转 `step × 4°`。灰色保持无彩色，核心保留输入 alpha。

**逐 RGB 通道 LUT 和上述 HSV 映射是 App 的近似选择，不是尼康亮度管线或已核实的厂家参数算法。** 不执行相机基底 TRC、厂家色彩矩阵、RAW 处理、锐化、中等范围锐化或清晰度；不从头字段额外推断 Gamma 并重复应用。模板自身的曝光、白平衡和既有处理也影响结果，无法代表真实相机与现场光线。

## 模板、后台处理与缓存

“设置 → 预览模板”可查看当前模板、通过系统文件选择器更换，或恢复内置模板。内置图片为 AI 生成的统一色调参考，包含肤色、蓝水、绿植及暖色物体；[来源记录](assets/preset-template-provenance.md)和[完整提示词](assets/preset-template.prompt.txt)随项目保留。它不是某款 NCP 的配套样片。

图片读取、方向归一化、缩放、摘要计算及渲染都在 worker 进行。模板来源最多 **20 MiB**，解码采样不超过 **1,000,000 像素**，最终长边最多 **960px**。自选模板在 App 私有目录保存为归一化 JPEG；透明区域合成在白底上，不修改用户原图。纯 Java 核心另有 4M 像素硬上限，不放宽 Android 模板处理的较小限制。

模拟图的内存缓存键包含原 NCP 的 SHA-256 标识、模型版本和模板版本。内置模板版本为 `neutral-synthetic-v1`；自选模板以**保存后的归一化 JPEG 内容 SHA-256**区分。先原子发布完整的内容寻址 JPEG，再读回校验哈希，最后提交模板设置；当前进程也使用保存后 JPEG 解码的像素，使重启前后输入一致。保存或设置提交失败保留原模板，读取时再次校验内容。更换模板后不展示后台旧任务的过期结果；缓存的模板像素、返回的模拟像素和原 NCP 互不改写。渲染结果使用既有 16 MiB 图像 LRU，未持久化为新的 NCP 或替换原文件。并发待处理图片达到上限时显示可点按加载的状态，暂时失败可显式重试。
