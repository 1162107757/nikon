# Huevia 照片直播 · 设计审核稿

这是独立的浏览器交互原型，供用户审核三种布局。未修改 Android 源码、版本、APK、后端或设备。照片复用既有概念素材，文件名、数量、项目、预设效果和进度均为示意。

运行 `node docs/design-review/photo-live-redesign/serve.mjs`，访问 http://127.0.0.1:8774/ 。服务器只监听本机，只提供此目录。

- A · 照片优先：项目和默认预设、固定传输区、最新照片、三列缩略图。适合日常边拍边看。
- B · 项目工作台：项目资料、已保存 / 待接收数量、固定传输区、三列照片，适合整理大量照片。
- C · 沉浸影棚：大照片、画布内传输浮层、胶片条；全部照片入口承接整理流程。

顶部可切换 11 种状态，并模拟一轮接收 → 保存 → 预设处理 → 等待。支持浅深色、单方案查看、项目和预设示意选择、详情、记录、照片放大、星标筛选、批量选择及偏好标记。停止直播保留照片；单张待完成不能进入批处理选择。选择偏好只影响本页，最终方案需在聊天中确认。

## 源码分析与后续实施边界

1. 接收字节约每 200ms 经 `AlbumController.java:911` 发布。`PhotoProjectPresets` 的原图进度监听会唤醒队列；在无新任务时仍 rebuild / changed，最终经 runtime 到 `MainActivity.syncConnectionState` 的 render，重建直播视图。
2. `AlbumPanel.java:1195` 的 fitHero 在布局后基于剩余空间再次改动主图高度；进度和重试操作用 GONE 显隐进一步改变状态卡高度。
3. 主图资源 key 包含接收状态，状态切换先释放已显示预览再解码，引入闪图。
4. 水平 liveProgress 经过 addSpaced 后被进度圈规则设成 32×32dp。
5. `PhotoLiveState.receivedBytes / totalBytes` 已有真实单文件字节进度，不需要额外相机请求。未知总量不用数字；字节达到 100% 后仍有协议响应、校验、落盘及相册发布，不能直接称“已保存”。

用户选定方案后，实施应先修无变化通知和整页重建链，再稳定视图与图片绑定，最后显示真实阶段及百分比。保留原有应用级 runtime、串行 PTP 队列、前台服务和后台连接；不通过重连刷新页面。

## 审核边界

浏览器原型的局部更新和几何检查不能证明 Android 真机闪动已修复，也不能证明后台传输稳定。正式实施后需针对原生视图更新、真实字节阶段、图片替换及前后台切换单独验证。当前只审核界面结构和状态表达。

素材来源见 assets/provenance.md。原始照片 atlas 与已有设计预览字节一致；Huevia 图标来自用户指定文件，未编辑。
