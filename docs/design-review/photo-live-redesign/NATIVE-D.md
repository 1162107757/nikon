## 对照实现

原生照片直播采用 D 的项目行、固定主图、左上默认预设、右上放大、底部 76dp 接收浮层、统计 / 接收记录、照片工具行和三列方形缩略图。主图正常手机窗口最高 284dp；字节、错误、等待和保存状态不会改变画布高度。按钮视觉紧凑，接收动作保留 44dp 点击高度。沿用 App 原有标题、连接状态、浅深色与底部导航。

默认预设和直播批量套用预设使用双列效果图与名称卡片；保留用户此前指定的原生全屏选择页，选中自动返回。窄屏或大字号改为单列，其他相册页面的既有单列选择页保持。原图、效果图和项目默认值继续分别管理；同一原图重复使用同一预设沿用原有复用逻辑。

项目菜单增加“新建项目”：直播中先提示停止，停止后打开名称与默认预设表单；未连接时沿既有连接引导及续接流程。浏览历史项目时，其他项目仍在接收或保存的浮层明确标注“其他项目”，避免把全局进度误认作当前历史主图。

## 闪动与进度

- `MainActivity` 仅在连接及壳层语义变化时重建页面；自动预设和照片租约通知不触发整页刷新。
- `PhotoProjectPresets` 忽略无实际队列变化的高频通知，移除字节事件引发的空重建链路。
- `AlbumPanel` 局部更新文字和进度；网格数据不包含字节计数。缩略图仅在照片身份改变时清空，主图以稳定来源键加载，新图就绪前保留已显示的像素与点击目标。
- 百分比来自当前原图的实际接收字节 / 总字节。未知总量只显示“接收中”。预览、接收、保存分阶段；100% 字节之后显示“保存中”，系统相册失败显示待重试并保留私有原图。
- “已保存”数量表示保留的原图文件；系统相册发布结果另外由保存阶段、待重试状态和接收记录表达。

## 验收证据与边界

最终原生证据位于 `.impeccable/review/photo-live-d-native/`，浅深色各自的 `report.json` 记录被测 APK 的 SHA-256。截图使用与设计稿相同的合成风景素材和手写测试预设；它们不是用户照片、相机实拍或 Nikon 效果等价证明，也不打包到产品。

原生检查覆盖连续 200ms 字节事件、照片操作租约进入 / 退出时的页面及 Bitmap 身份、重复解码、画布和列表边界；保存、未知总量、失败、准备、等待及停止状态；筛选与选择保持主图；双列效果选择、自动返回；预览升级原图的旧图保留、切项目清空及过期回调拒绝；新建第二项目入口与取消保留原项目。

构建、签名、测试计数、独立复核及实体手机安装结果以 [本版交付记录](../../../dist/nikon-usb-0.9.11-beta-VALIDATION.txt) 为准。模拟器状态注入验证 UI 更新行为，不替代真实相机连续拍摄、无线吞吐、锁屏或系统相册实际发布测试；本轮没有更改 Wi-Fi、PTP 会话或后台保活策略。
