## 页面与交互

项目选择和详情位于画布上方。固定高度画布保留 C 的沉浸构图：左上切换项目默认预设，右上放大，底部深色浮层显示当前原图进度及停止、重试或连接操作。其后依次为保存 / 待接收数量与接收记录、照片数量 / 星标筛选 / 选择、A 的三列方形缩略图。

点历史照片独立查看，支持切换、星标及紧凑的相册保存状态入口；上方直播主图不随筛选、选择或浏览历史改变。项目详情可查看创建时间、已保存数量、默认预设与容量，并可重命名。批量选择包含可见已保存照片的全选、星标和套用预设，当前接收或待重试照片不能参与批处理。

默认预设和批量套用使用含效果图与名称的选择页，选中后返回；默认选择还包含“不使用预设”。默认预设仅影响之后接收的照片，批量套用只操作已选原图，不改项目默认值。所有照片、文件名、项目和容量均为模拟数据；批量后的 CSS 色彩变化仅表达交互，不能代表真实 NCP 解析或预设效果，亦未执行真实文件保存。

## 状态与验证

固定画布、76px 传输槽位与照片工具行覆盖接收、等待、准备、大小未知、保存、预设处理、完成、失败、断开、停止和空项目共 11 个阶段。空项目保留画布空态且禁用放大。主图查看使用明确的当前 / 最近保存照片记录，避免点大图误开其他网格照片。初次检查发现空态滚动条出现与消失引起宽度变化，已用稳定滚动条槽位修正。

证据保存在 `.impeccable/review/photo-live-combined/`：

- `functional.json`：默认预设切换为 Agfa Optima；星标筛选后可见 3 张，批量为这 3 张套用 Bluesky 后，默认仍为 Agfa Optima，主图未变化。
- `state-layout.json`：11 阶段中画布、传输区、照片标题及网格起点的最大几何差为 **0px**。
- `desktop.png`、`mobile-light.png`、`mobile-dark-error.png` 与预设选择页截图：覆盖桌面、窄屏、浅深色及失败状态。移动端横向溢出为 0，画布预设按钮高 44px；后两项由本轮主执行者测量，未单独写入上述 JSON。

新鲜评审检查了布局截图与源码，指出主图放大记录错误及空态可打开照片两项问题。修复后，评审对这两项限定复核给出 **SHIP**，确认两项已解决。实际浏览器随后验证等待与保存阶段放大均与主图使用相同的图像资源，文件分别为 DSC_0127 / DSC_0128；空项目禁用放大，见 `hero-identity-check.json`。

原稿入口点击回归仍显示 3 套方案，见 `original-review-retained.json`。`preserved-originals.json` 核对本轮前后 `index.html`、`review.css`、`review.js` 的 SHA-256 完全一致。这里的布局验证只证明浏览器原型稳定，不能据此宣称真机闪动或后台传输已修复。

## 原生实施边界

正式百分比须来自当前原图的实际已接收字节 / 总字节；总量未知时显示接收状态，不编造比例。100% 后单独显示保存阶段，原图落盘并成功发布到系统相册后才计为已保存；预设效果处理另列。原生应保留上一张可用图直到新图可展示，局部更新状态，避免重建整页和反复清空图片。

连接继续由现有应用级 runtime、串行 PTP 队列及前台服务管理；项目筛选、批处理和页面状态更新不应主动重建会话。后台与锁屏稳定性、相机热点状态、真实 JPEG 传输及相册发布仍需在后续实现中单独验证。
