导出看得明白，任务说得清楚

本轮剩下的页面：导出设置（三档 / 自定义 / 已存在相册）、原始文件确认、批量进度、结果汇总与失败恢复。 信息顺序沿用已批准的需求 5.1，密度收紧、底部主操作吸底，所以 1.3 字号下按钮不会压住错误文案。 下面每台手机都可以直接点。

设计稿 v2 · 待审核
字号 1.3 倍下内容区自己滚动，底部按钮与行内错误各占各的位置 —— 这是 v1 最容易出事的地方。
1 · 导出照片 · 完整尺寸（默认） 可点档位、「保存到」、展开内容尺寸、底部原始文件入口。

规格数字从 40sp 降到 24sp，省下的高度给了「保存方式」与体积状态。 有边框时才出现可展开的「内容尺寸 / 导出尺寸」，没边框不占位。

2 · 导出照片 · 自定义 把长边改成 500 看行内错误与主按钮禁用；质量滑块可拖。

长边 640–8192 且不放大，质量 70–100 整数。错误文案在输入框正下方， 不靠吐司，主操作同时禁用。

3 · 导出照片 · 相册已有同一结果 主操作变「查看已保存照片」；勾「另存新副本」后才变回导出。

同规格已核对存在时默认不重复生成；额外副本必须用户显式勾选，并明确说明 新副本使用本次时间，避免以为照片丢在相册旧日期。

4 · 批量导出 · 处理中 点「停止后续」看取消的中间态文案。

阶段状态写「准备原图 / 生成照片 / 核对结果 / 保存到手机相册」， 不编造平滑百分比；进度条只表达已完成张数。

5 · 结果汇总 点「重试失败项」看只处理必要项。

四类分开计数：新保存 / 复用已保存 / 失败 / 未处理，每项可看原因。 重试保持其冻结规格，成功项不重复。

6 · 异常：相册核对不可用 成品已生成但相册未完成，可单独重试发布。

不谎报成功、不重做像素处理。状态不明时写「暂无法核对已保存照片」， 重试不会隐式变成新副本。

相对 v1 导出稿的改动

信息顺序不变（照片摘要 → 三档 → 实际尺寸与质量 → 保存位置 → 保存方式 / 已有状态 → 预估体积与原图保护 → 主操作）。改的是密度与状态表达。

部件规格说明
页面骨架内容区可滚动 + 底部操作吸底 48dp 以上触达 改 v1 是整页流式，1.3 字号下底部按钮会盖住预估体积与错误文案。
规格数字24sp 粗体 + 11.5sp 副说明 改 从巨号降级；「格式 / 质量」收进同一张卡的键值行，不再各占一整行。
内容 / 导出尺寸可展开，仅有边框时出现 留 输入口径一律是最终含框成品画布；分享 2048px 同口径。
自定义输入数字键盘输入框 + 质量滑块；行内错误在输入框下方 改 错误不走吐司，主操作同步禁用；失焦只规范空格，不悄悄截断成别的合法值。
保存方式独立分组：已有状态说明 + 「另存新副本」勾选 改 v1 把它混在「保存到」一行里；现在已有 / 被删 / 不可核对三种状态各有自己的文案与动作。
预估体积范围 / 估算中 / 实际 / 不可用 四态 留 默认一位小数范围，估算不可用不阻止导出；完成后展示实际大小。
原始文件入口主按钮下方低强调文字 + 确认弹窗 留 仅在有可信关联的完整 JPEG 原图时显示；确认文案写明不应用当前调色、也不使用上方尺寸质量设置。
批量进度阶段状态 + 已完成张数 + 逐张行 改 取消时先写「正在取消，等待当前步骤结束」，不立刻写「已取消」。
结果汇总四类计数 + 逐项原因 + 仅重试失败 / 未处理 改 v1 没有结果页；这里补上，发布成功但记录写回失败时以发布结果为准。
