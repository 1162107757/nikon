# 图片细节、导出与直方图 · 详细需求 v1

状态：**用户已通过“开始”批准本需求与正式设计图，进入 0.19.0-beta / 91 实现与验证阶段。**

日期：2026-10-24。以现有 Android 原生编辑器、暖白／石墨色和桃色强调色为基础。以下为批准范围；完成情况以实现记录和验证证据为准。

## 1. 目标、边界与现状

### 1.1 用户目标

1. 修完照片后，能确认眼睛、毛发、纹理等真实细节，而不是继续放大编辑缩略图。
2. 保存前清楚知道成品的像素尺寸、质量、去向及是否会产生额外副本。
3. 调节时看得见照片整体明暗和 RGB 分布，用预览警示辅助判断高光和暗部。
4. 大图、取消、断权或失败后，原图、草稿与已成功保存的照片仍可信。

### 1.2 本轮范围

| 本轮实现目标 | 明确不在本轮 |
| --- | --- |
| 独立全屏细节页：适应、100%、200%、拖动定位、同构图调色前后对比 | RAW 解码、AI 超分、降噪、修复／去人、局部画笔 |
| 完整尺寸／分享／自定义三档 JPEG 导出，单张与批量统一参数 | PNG、HEIF、AVIF 导出，HDR 输出，广色域保留 |
| 编辑器内可收起的直方图、预览高光／暗部警示 | 曲线、HSL、色轮、局部直方图、波形图、斑马纹阈值自定义 |
| 原图保护、按实际成品去重、已保存提示、显式“另存新副本” | 新的底部导航 Tab，推翻现有编辑／预设／配方／构图／边框结构 |

曲线与 HSL 作为下一阶段单独设计与审核，本轮不预留不可用按钮。

### 1.3 已核对的现状

| 代码依据 | 当前行为 | 对本次设计的约束 |
| --- | --- | --- |
| `PhotoFilterEditor.bind()/decode()` | 编辑主预览以长边 1280px 为目标；小图不放大；滤镜缩略图更小 | 现有预览不能冒充原尺寸细节 |
| `PhotoFilterEditor.showExport()` | 展示 JPG、构图／边框后的尺寸，转入现有保存位置流程 | 在这个入口扩展，不增加平行保存流程 |

| `PhotoEditStore.Draft.identity()` | 按原图字节 SHA、预设、强度、手动调节、构图和边框识别草稿 | 导出规格要独立于编辑身份，不能修改参数就串用旧结果 |

| `LocalAlbumPanel.confirmPng()` | PNG 源文件保留，用户确认后以白底 JPEG 工作副本编辑 | 本轮保持这一明确转换提示，不声称导出透明 PNG |

本轮所有新增处理发生在本地。既有相机 NEF 原文件保存入口保持独立，不附带手机编辑效果。

## 2. 页面结构与主流程

### 2.1 编辑页

- 保留现有返回、照片版本、编辑分组与导出入口。
- 图片工具区增加“细节”入口；图标配可访问名称“查看真实细节”。不把双指放大作为唯一入口。
- 图片附近增加“直方图”展开／收起按钮，展开后显示一条紧凑统计区；不永久占用照片大面积空间。
- 高光／暗部警示在统计区操作，打开后仅叠加到照片内容，不进入保存结果。
- 导出按钮进入新版“导出照片”设置面板。

### 2.2 单张流程

`打开本地完整照片 → 编辑 → 看直方图／警示 → 查看细节 → 返回继续编辑 → 选择导出档位和保存位置 → 生成／核对／保存 → 查看结果`

细节页和导出面板均绑定打开时的同一份照片与编辑快照。全屏页返回后保持原编辑分组和滚动位置，不重置参数。

### 2.3 批量流程

`选择照片 → 现有批量编辑／保存入口 → 同一份导出设置面板 → 汇总实际规格与数量 → 冻结逐张任务 → 逐张处理 → 成功／失败／取消汇总 → 仅重试失败项`

批量界面不提供逐张细节编辑；用户可退出批量状态进入单张查看。不同长宽比、构图及边框必须逐张算尺寸，不展示虚假的“全部 2048 × 1365”。

## 3. 真实细节页

### 3.1 内容语义

对于参数与原图关联可可信核对并恢复的当前编辑，页面标题为“细节预览”，分段为“当前效果 / 调色前”。下表和“同构图、不含边框”的承诺仅适用于这一情况；历史JPEG例外见下文。

| 模式 | 显示内容 |
| --- | --- |
| 当前效果 | 完整本地 JPEG 基础上的当前滤镜、强度与手动调节，再按当前构图显示；不含外加边框 |
| 调色前 | 同一完整本地 JPEG、同一构图，移除手机滤镜与手动调节；不含外加边框 |

两模式共用构图矩阵、中心锚点和缩放倍数，切换时不跳位置、重置缩放或回到整图。不称“原图”，避免与既有完整未裁切原片入口混淆。页内常驻说明“同构图对比 · 不含边框”。现有编辑页的原图对比行为不改。

“调色前”仍是相机／导入 JPEG 已经形成的像素，不声称是线性 RAW、相机未处理传感器数据或 NX Studio 结果。

若显示的是缺少可信参数／原图关联的历史保存版本：按**整张已保存JPEG的真实像素**查看，包括其中已经烘焙的内容、留白、Logo与边框；不能猜测剥离边框、恢复构图或套用当前新草稿。页面标“已保存版本”，说明改为“查看完整文件像素”，不显示“同构图对比 · 不含边框”。“调色前”禁用并说明“此版本暂无法恢复调色前内容”。该JPEG仍可适应、100%、200%与定位查看，100%的数据源就是这张完整已保存文件。

### 3.2 100% 的准确含义

- **100% = 被查看内容中的 1 个像素，对应屏幕的 1 个物理像素**：可恢复当前编辑采用构图后、未加边框的照片内容；历史JPEG例外采用整张已保存文件的全部像素。不是1dp、1 CSS像素，也不是编辑预览缩略图的1个像素。
- EXIF 方向、旋转、拉直和裁剪按成品内容相同规则计算。拉直涉及的插值属于现有构图，不将插值后的像素声称为额外光学细节。
- 可恢复当前编辑的外加边框不参与细节尺寸、定位图或缩放计算，边框可在编辑页与导出摘要中查看。历史JPEG例外中，已烘焙边框属于文件像素，必须参与尺寸、定位图和缩放；不执行推测去框。
- 200% 是同一内容像素放大到 2 × 2 屏幕像素，仅辅助观察；说明“放大查看，不增加细节”。
- 拟合模式按钮为“适应”，按可用画布容纳整幅构图后内容；百分比显示实际倍率。适应倍率为 `min(1, 可用宽/内容宽, 可用高/内容高)`，小图居中显示100%，不为了填满画布自动放大。
- 原生渲染必须关闭系统资源密度缩放，坐标计算使用屏幕实际像素。测试不能用 dp 换算后宣称 1:1。

### 3.3 操作与位置

1. 首次进入以“适应”显示并给短提示“点按 100% 查看真实像素”。默认不要直接把用户带进无法辨认位置的局部。
2. 底部紧凑控制：适应、100%、200%；当前选项包括文字与背景的完整选中态。
3. 双击照片在“适应 ↔ 100%”间切换，以双击点为中心；捏合范围从适应倍率到 200%，低于 100% 的实际百分比保留整数显示。
4. 放大时单指拖动；到边缘保持边界，不能拖出整屏空白。图像小于画布的轴居中。
5. 放大时右下角显示小型整图定位图和当前视口框，可点按／拖动定位。定位框只反映照片可见区域，不能覆盖操作按钮。
6. 模式切换保留同一逻辑锚点；新模式局部未完成时保持上一有效内容，并清楚显示“正在载入当前效果／调色前”。不能将旧模式冒充新模式。
7. 返回键和顶部返回行为一致，不产生编辑撤销记录、不自动导出。
8. 不在全屏细节页调整滤镜／曝光等参数；调节统一回编辑页。避免“画面是旧快照、滑块是新参数”的歧义。

### 3.4 局部读取与效果一致性

- 只从已校验的本地完整 JPEG 或已保存完整结果读取。相机缩略图、1280px 主预览、256px 滤镜图均不能作为 100% 数据源。
- 优先使用按可见区域读取与有界瓦片缓存。未加载区域可先显示低清底图，但必须带“正在载入细节”，真实瓦片到齐前不能用清晰度标签暗示已完成。
- Tile 按完整图坐标处理滤镜／强度／调节，带足空间滤镜、构图插值的 halo；真实图边缘使用与整图渲染相同的扩展规则。Tile 边缘不能充当原图边缘。
- 手动清晰度／锐化的半径以**完整源图尺寸**计算；预设固定半径规则维持现有模型。不能根据瓦片长边、视口或屏幕密度重算。
- 有先后顺序的空间滤镜所需 halo 应合成计算，不仅取最大单层半径。Tile 内部禁止先缩小再锐化冒充完整渲染。
- 若某个效果模型暂不支持完全一致的局部处理，可在独立后台生成有界／磁盘暂存的完整分辨率效果再读取。失败时显示无法载入，不回落为假 100%。
- 对可恢复当前编辑，细节数据定义为**JPEG编码前的完整分辨率、未加边框的编辑结果**；不会模拟质量90／95的压缩噪点，文案“细节预览不代表导出压缩效果”。缺少可信参数／关联的历史保存版本直接解码其整张已有JPEG，包含已烘焙边框，不再应用滤镜或剥框；按“已保存版本 / 查看完整文件像素”标识并禁用调色前。
- 验收必须与整图编码前的同位置输出对照；默认照片与缩放不会暴露接缝不够，需用高反差、角落、拉直和高锐化夹具核对。

### 3.5 生命周期和缓存

缓存键至少包含账号范围、原图字节身份、编辑快照身份、模型版本、构图、模式、瓦片坐标和像素级别。失效条件包含照片切换、同图重新绑定、账号切换、草稿变化、源字节变化和页面关闭。

返回／切换后取消不再需要的请求；完成回调核对页面 generation 与快照身份，不能把旧照片／旧参数结果贴到新页面。缓存遵守有界 LRU，进入后台释放可重建大块，保留来源与视口即可。内存不足提示“细节暂时无法载入，返回后可重试”；不能崩溃、无限重试或改写原图。

## 4. 直方图与预览警示

### 4.1 统计对象

- 统计**当前编辑效果的完整构图内容**，包括滤镜、强度、手动调节、旋转／拉直／裁剪；排除边框、留白、Logo、UI 和警示叠层。
- 使用现有 sRGB 预览的 8 位结果，注明“预览统计”。不声称是完整原图逐像素统计、线性曝光测量、RAW 通道或相机直方图。
- 统计不随细节页 ROI、平移或屏幕缩放改变。裁剪、调节或滤镜改变时按新快照更新。
- 对边框外加白底／黑底的照片，直方图不能被新增纯白／纯黑边框淹没。
- PNG 经现有确认转成白底 JPEG 工作副本后，统计以该副本内容为准，白色透明区域属于工作内容；不把原始透明像素当黑色计入。

### 4.2 展示和计算

1. 提供“亮度 / RGB”两种显示；默认亮度。模式只是显示方式，不改变照片与导出。
2. 每通道 256 个区间，x 轴固定 0–255，从暗到亮；无数据／解码失败与“全黑”的有效直方图区分。
3. 亮度采用编码 sRGB 的 `Y = round(0.2126R + 0.7152G + 0.0722B)`，各值 0–255，明确是显示亮度指标。RGB 三线使用同一份像素样本与共享纵轴。
4. 纵轴按该快照最大计数归一化，三条 RGB 曲线共用最大值，不能各自缩放到相同高度而掩盖通道相对分布。
5. 不自动裁去两端峰值。使用轻填充／细线和端点警示符，避免峰值压满区域导致全图不可读；如需仅对显示做压缩，要给固定一致的映射，不改变计数。
6. 空间不足时可将 256bins 合并为相邻 bins 展示，统计数据仍保留 256bins。放大字体不裁切控制。
7. 滑块拖动可节流至约每 200ms 一次；松手后必须完成最终快照。更新中显示“更新中”并保持上一份有效图，不能清空闪烁。
8. 新结果只有在账号、原图和编辑快照身份仍匹配时才能提交。只允许最新请求生效。
9. 高光／暗部按下节固定规则统计；未完成或无数据时不显示伪造的 0%。

### 4.3 警示交互

- **高光警示**：预览像素任一RGB通道等于255；即至少一个通道触顶。提示名称为“高光警示”，帮助文案明确可能只是单通道到顶，不声称整像素已经纯白。
- **暗部警示**：预览像素R=G=B=0；仅完全黑色触发，避免把饱和红／蓝等因某个通道为0的像素误判为黑影。
- 两者百分比均以有效预览像素总数为分母，分别计算命中像素占比，保留一位小数；真实非零但小于0.1%显示“<0.1%”，真正零显示“0%”。图稿示例值不能当实测值。
- 两种像素条件互斥，不会同一像素同时命中；两开关可同时开启。高光使用暖色斜纹、暗部使用蓝色斜纹，保留图案和图例避免只靠色觉区分。
- 高光和暗部可分别开关，状态以文字／图标与选中背景共同表达；不能仅靠红／蓝颜色。
- 警示仅在照片内容叠加，不影响滤镜缩略图、直方图数据、细节输出、导出像素或成品身份。
- 预览采样命中区域可以半透明图案显示，不能把低清统计轮廓声称为逐原图像素的准确遮罩。
- 简明说明：“基于当前 sRGB 预览，辅助判断；不代表原片细节一定不可恢复。”
- 开关属于查看偏好，不进入草稿、不进入撤销／重做、不算未导出改动。
- 默认收起直方图、两警示均关闭；同张照片本次编辑内保留用户开关。切换照片、账号或重新进入编辑时恢复关闭，不因查看一张高调作品而让下一张默认被大面积斜纹遮住。

## 5. 导出设置

### 5.1 共用导出面板

面板顺序：照片／数量与当前版本摘要 → 三档选择 → 实际尺寸与质量 → 保存位置 → 保存方式／已有状态 → 预估体积与原图保护说明 → 主操作。

| 档位 | 规格 | 默认行为 |
| --- | --- | --- |
| 完整尺寸 | 当前构图及边框决定的完整成品尺寸，JPEG 95，sRGB | 每次新打开导出面板默认选中；不设 8192px 人为长边上限 |
| 分享 | 最终成品长边不超过 2048px，JPEG 90，sRGB | 只缩小不放大；源不足 2048 时使用其实际完整尺寸 |
| 自定义 | 最终成品目标长边 640–8192px，质量 70–100，sRGB | 同时受当前完整成品实际尺寸约束；不允许放大 |

完整尺寸不表示未裁切原始像素尺寸，副文案写“保留当前构图与边框的完整尺寸”。界面同时显示“内容尺寸”与最终“导出尺寸”可在有边框时展开查看。输入的长边一律以**最终含框成品画布**为口径，分享 2048px 也按同一口径。

完整成品自然尺寸应先按现有构图和边框尺寸规则求出，再按比例缩小整体画布。共享／自定义缩小时边框、Logo、文字一同缩小，保持与完整成品一致的构图比例；不能先缩小内容再套固定字号边框，导致档位改变设计比例。

### 5.2 尺寸规则

- 非完整尺寸的目标长边 `L`：`scale = min(1, L / max(Wfull,Hfull))`；长边取实际目标，另一边按原比例四舍五入、至少 1px。最终摘要必须显示最终整数宽 × 高。
- 自定义输入区提供数字键盘与滑块／步进之一；不能只有难以精确操作的滑块。质量以整数 70–100，显示“JPEG 质量”，不能误写成“保留 90% 画质”。
- 第一次切到自定义时，长边填 `min(4096,完整成品长边)`、JPEG质量90（可调70–100）；若完整成品小于640则按下条禁用。当前面板内切换档位可记住本次已输入值；重新打开面板仍默认完整尺寸JPEG95，不暗中沿用上次低质量设置。设计图中自定义长边2048是用户修改后的演示值，不是首次默认值。
- 自定义上限是 `min(8192, max(Wfull,Hfull))`。源完整成品长边小于 640px 时，自定义尺寸禁用并说明“此图长边不足 640px，可选完整尺寸”；分享仍可选但不能放大。
- 任何档位都不自动改变裁剪比例、旋转方向或边框样式。
- 原图大于 8192px 时完整尺寸仍可选。能力受内存／编解码限制时给真实失败，不把完整尺寸偷偷改成 8192px。
- 无效数字、空值、溢出、越界、粘贴字符显示行内错误并禁用主操作；失焦可以规范空格，不能悄悄截断成别的合法尺寸。
- 分享与某组自定义参数得到相同实际尺寸、格式、质量、色彩与元数据策略时，是同一导出规格；不能仅因档位名称不同而重复生成结果。

### 5.3 体积估算

- 设置面板标“预估体积”，默认以一位小数的范围表达，例如“约 4–8 MB · 实际以导出为准”；图稿数值为示例，实际必须依照片和设置更新。
- JPEG 内容复杂度、噪点、质量、边框比例均影响体积，不能只按像素面积和固定压缩率给单个精确 MB，更不能承诺目标文件一定小于某体积。
- 可用代表性采样／代理编码与经过验证的区间模型估算。估算异步、可取消、按完整导出快照缓存；无可用可靠估算时显示“导出后显示实际大小”。估算不可用不能阻止正常导出。
- 估算中保留上次值并明确“估算中”；切换照片／设置后不能将旧值当新值。实际已编码且校验通过的文件可展示“实际 5.2 MB”。
- 批量有完整估算时显示总范围；存在未知项时明确“已估算 X / N 张”，不能将已估算小计冒充总计。
- 空间预检计入工作位图／暂存与目标写入的需求。估算压缩文件体积不能充当内存需求估算，也不能替代写入过程中的剩余空间检查。

### 5.4 保存位置与副本

保留现有“仅保留在应用 / 同时保存到手机相册”两种位置。新增档位不绕开已有发布器、原图关联与回执核对。

| 状态／操作 | 应有行为 |
| --- | --- |
| 同一可信输入、编辑、模型和实际导出规格已存在 App 结果 | 核对后复用，不再次编码；摘要写“已生成，可直接保存” |
| 同一结果已核对存在手机相册 | 默认主操作显示“查看已保存照片”，不重复新增；可显式选“另存新副本” |
| 相册结果被用户删除，App 结果仍完好 | 提供“重新保存到手机相册”，核对缺失后重新发布 |
| 相册文件被修改／归属或权限不确定 | 显示“暂无法核对已保存照片”；不覆盖、删除或假定已丢失。不明状态的重试不能隐式变成新副本 |
| 显式另存新副本 | 新相册条目、唯一发布请求；按既有规则使用本次时间，更新副本的时间相关元数据，不更改 App 规范成品与源照片 |
| 上次发布中断后重试 | 恢复同一次发布请求，不因为“另存”标记再多造一份 |

结果身份至少包含：可信输入 SHA、完整编辑身份、渲染模型版本、实际输出宽高、JPEG 质量、色彩空间、元数据策略及编码策略版本。保存位置与“额外副本”属于发布行为，不能污染可复用的规范像素结果。文件名／友好预设名不是可信身份。

默认完整尺寸 JPEG 95 与既有结果兼容时应沿用／迁移已有身份和回执，不在升级后把全部旧成品当成未保存。不同质量／尺寸绝不能串用同一结果缓存。

### 5.5 原图、保存版本和元数据

- 从可信原图与可恢复编辑参数生成新规格；缩小只影响新成品，不改变草稿、原图和已有完整成品。
- 选中一个历史保存版本时，不擅自套用这个原图当前的新草稿。如其参数不可恢复，仍可把选中的 JPEG 作为已烘焙的成品缩小／重新编码，面板注明“基于已保存版本”，不能表示为重新从原图渲染。
- 无编辑的 JPEG 导出设置也按当前请求的质量编码；不能将“JPEG 95”错误表示为质量未知的原片复制。本轮新导出设置页在主导出按钮下方提供低强调文字入口“保存 JPEG 原始文件”，与三档编码导出明确分开。入口仅在有可信关联的完整JPEG原图时显示；不能把PNG白底工作副本或已有滤镜成品称为原始文件。
- 点“保存 JPEG 原始文件”先确认：“保存未编辑的JPEG原始文件？不会应用当前滤镜、调节、构图与边框，也不使用上方尺寸和质量设置。完整保留原文件内容及其已有信息（可能包含定位）。”确认按钮为“保存原始文件”，取消返回当前设置。保留当前草稿，不标记其已导出。该操作沿用已有普通发布去重，不提供会改时间元数据的额外副本方式，不为保留字节而重新编码。
- 新入口复用现有选中JPEG保存能力，而不是宣称当前编辑面板已有此入口。现有能力路由是`AlbumPanel.exportCurrentJpeg()` → `saveToGallery()` → `PhotoAlbumSaver`／已有发布器；新增轻入口应单独选择保存位置且令`PhotoSaveChoice.allowNewCopy=false`，最终调用相同的`saveChosenPhoto(verifiedOriginal,target,false)`能力，不直接调用会开放新副本选项的现有`saveToGallery()`UI。必须传入验证后的JPEG原图且冻结 `forceNewCopy=false`。当前编辑页`PhotoFilterEditor.showExport()`只有主保存按钮与可选NEF动作，因此本轮需要新增这个轻入口。PNG原始文件保留现状，不在本轮新增PNG发布能力；NEF原文件沿用其现有独立入口。
- 输出固定 8 位 sRGB JPEG；不复制不兼容 ICC，不宣称保留 Display P3、Adobe RGB 或 HDR。预览与输出都走显式 sRGB 转换。
- 保留现有捕获元数据白名单：相机／镜头、快门、光圈、ISO、焦距、曝光偏差、拍摄时间及时区等。保持现有精确有理数值处理，快门 `1/640` 不能变成 `1/666` 等近似写回。
- 不复制 GPS、原文件缩略图、原缩略图偏移和其他不安全／不兼容块；本轮不增加“保留定位”开关。
- 三档JPEG编码导出的面板元数据区域使用静态说明“保留拍摄信息 · 不含定位”；不以技术白名单字段占据主流程。该说明不适用于轻入口的原始文件复制，后者确认文案明确原文件信息完整保留。
- 若旋转像素／构图／边框／缩放时已按正确方向生成画布，写 Orientation=1，写真实像素宽高；不能同时烘焙旋转又保留 EXIF 旋转导致系统相册转两次。
- 常规保存保持现有拍摄时间策略；仅显式“另存新副本”按现有副本规则使用本次时间。界面说明“新副本使用本次时间”，避免用户误判照片丢在相册旧日期。
- 文件名可带便于识别的尺寸／质量后缀，但不改源文件名；同名冲突由唯一内部身份解决，不覆盖别人的文件。

## 6. 单张／批量任务状态

### 6.1 接受前

准备编辑快照、核对输入与账号、计算每张实际尺寸，参数非法／输入不可读时不启动。用户在导出设置面板返回不会产生新成品、相册副本或“已导出”状态。

确认后冻结逐张：输入与版本、账号、编辑参数、模型、几何／边框、规格、保存位置、是否新副本、发布请求身份。用户随后继续编辑、切换照片或重绑UI，不改变、不取消已接受任务；任务继续处理接受时的冻结快照。这些UI变化只使尚未接受的估算、细节和直方图旧请求失效。切账号也不能将旧任务重定向至新账号；账号权限等真实执行条件变化按第7节停止或失败。

导出完成后，只有当前草稿身份仍与该任务的冻结编辑快照完全一致，才能将它标记“已导出”。用户已产生新草稿时，仅登记旧快照的成品／发布结果，不能把新草稿误标已导出，也不能以旧快照覆盖新草稿。

### 6.2 处理中

状态分为“准备原图／生成照片／核对结果／保存到手机相册”，显示完成张数和当前项。进度只表达已完成工作；编解码无真实字节进度时用阶段状态，不编造平滑百分比。

逐张串行，后台线程处理，主线程可响应取消、返回和页面切换。单张使用同一任务机制。批量不持有全部原图位图，不并行解码多张完整大图。

取消后不再开始新项，当前项在安全点停止。取消发生在不可中断的编码／系统提交阶段时写“正在取消，等待当前步骤结束”，不能立即写“已取消”却继续不受控新增照片。

### 6.3 结束与重试

结果区区分：新保存、复用已保存、失败、未处理／已取消。示例“已完成 8 / 10 张：新保存 6，已保存 2，失败 1，未处理 1”。每项可看原因。

仅重试失败／未处理项，保持其冻结规格；成功项不再重复。发布成功但草稿历史写回失败时，以已确认发布结果为准，重试修复记录不能再发一份。

本轮维持现有进程内任务与发布恢复边界，**不承诺 App 被系统杀死后自动续跑整个批量队列**。已提交文件／发布回执必须可恢复；未完成队列可由用户重新发起并按身份去重。完整持久任务队列单独列后续阶段。

## 7. 异常与限制

| 场景 | 反馈／恢复 | 必须保护 |
| --- | --- | --- |
| 相机照片只有缩略图或完整原图未下载 | “需先获取完整照片”；沿用已有获取动作，不展示假 100% | 缩略图不变成完整导出源 |
| URI 授权失效／选中项被移除 | “照片读取权限已变化，请重新选择”；保留设置供重试 | 不扩大读取其他手机照片权限 |
| 仅部分照片授权 | 只处理已选择／授权项；不要求全相册权限作为前提 | 不扫描未授权相册 |
| 相册写入／核对不可用 | 成品保留 App，明确“照片已生成，手机相册保存未完成”；可重试发布 | 不谎报成功，不重做像素处理 |
| 存储不足 | 停止当前项，显示释放空间后重试；清理自己未提交的临时文件 | 原图、草稿、成功项不删 |
| 大图／完整处理内存不足 | “完整尺寸处理内存不足，可选择分享尺寸后重试”；不能自动切换档位 | 源图尺寸和成品身份不变 |
| 分享档位仍需完整效果处理而内存不足 | 如不能分块安全完成，诚实失败；不能承诺选分享一定解决内存 | 不先降采样再用错误空间半径冒充同效果 |
| JPEG 损坏／截断／解码失败 | 标记当前项失败，可重试读取或重新导入 | 不将部分文件发布为成品 |
| PNG | 沿用现有白底工作副本确认；页面说明，源 PNG 保留 | 不承诺透明度、无损或PNG格式导出 |
| NEF／其他 RAW | 只保留已有原文件保存能力；不提供本轮编辑效果导出 | 原始 RAW 不改写 |
| 其他未支持格式 | 显示格式不支持，不仅按扩展名伪装 JPEG | 不错误编码、不覆盖 |
| 接受后继续编辑、切换照片、重绑UI | 已接受任务继续按冻结快照执行；仅丢弃未接受的旧估算／细节／直方图请求 | 不改任务参数，不把新草稿标已导出 |
| 接受后源字节改变、冻结快照损坏／不可读或所需来源失效 | 核对真实失败原因，当前项失败；按影响停止剩余相关项并保留可重试状态 | 不使用变化后的源／当前新草稿顶替冻结输入，不发布不一致结果 |
| 执行期间账号范围或读写权限失效 | 不转到新账号或扩大权限；当前项按原因失败／停止，剩余需该权限项停止处理并明确反馈 | 旧任务结果只归冻结账号；已完成项保留 |
| 退出细节／页面重建／旋转 | 取消旧绘制，恢复可信快照与锚点；无法恢复则安全返回编辑页 | 不提交旧页面回调 |

## 8. 视觉、可访问性与适配

- 沿用现有暖白、暖灰、石墨、桃色与细线图标；不重画主 Tabbar，保持现有悬浮样式与整项选中范围。
- 细节照片画布用低干扰中性底；工具和信息区在浅／深色分别使用可读对比，不把整个编辑器变成另一套视觉系统。
- 点击目标至少 48dp；文字使用 sp，1.3 倍字体不裁切；横屏、窄屏支持滚动，不让固定底部按钮盖住参数或错误文案。
- 区分“100%”缩放与“JPEG 质量 95”，不可两处都只写百分数而无标签。
- 当前效果／调色前、直方图模式、档位和警示开关都有文字及完整选中态。禁用项给原因，可被辅助功能读出。
- 屏幕阅读器可读模式、实际缩放、图片尺寸、载入状态和导出结果；直方图提供文本摘要，不只提供不可理解的图形。
- 定位图可由拖动实现，但还须能用 100%／适应快捷操作；关键流程不依赖多指手势。
- 尊重减少动画偏好；不为统计加载加持续闪烁，更新时布局不跳动。

## 9. 实现前必须落实的验收清单

### A. 真实细节

- [ ] 1px 棋盘／单像素线 JPEG 夹具：100% 时原生 framebuffer 确认 1 内容像素对应 1 物理像素，多个屏幕密度相同。
- [ ] 适应／100%／200%、双击、捏合、拖动边缘与定位图一致；200% 不增加数据分辨率。
- [ ] EXIF 1–8、90°旋转、拉直、裁剪与窄长图：尺寸、朝向、视口锚点无误。
- [ ] 可恢复当前编辑的当前效果／调色前同构图、同中心、同缩放；移除手机调色且排除外加边框，既有完整原片入口不变。
- [ ] 无可信参数／关联的历史JPEG按完整文件真实像素查看，含已烘焙边框；标“已保存版本 / 查看完整文件像素”、禁用调色前，不出现“不含边框”承诺且不推测剥框。
- [ ] 多种预设、强度 0／50／100、手动锐化／清晰度极值：区域结果与整图编码前对应区域核对，tile seam／halo 边界无突变。
- [ ] 不能从1280px预览生成假细节；未就绪／不支持明确反馈。
- [ ] 同图重绑、快速切图、切账号、返回、旋转、OOM 均无旧回调污染与崩溃。

### B. 直方图／警示

- [ ] 纯黑、纯白、灰阶、纯 RGB、双色峰值等夹具：256bins 和亮度公式正确，RGB共用纵轴。
- [ ] 改边框不改统计，改裁剪／曝光会改统计；缩放／拖动不改统计对象。
- [ ] 快拖滑块只有最新快照更新，松手后统计匹配最终照片；错误状态与有效零值区分。
- [ ] 高光任一通道255／暗部三通道全0及百分比固定规则正确；单色红、蓝不触发暗部警示，双开关可同时使用。
- [ ] 警示与图表不进入导出、不改草稿身份、不进入撤销记录。
- [ ] 图表有“预览统计”，不声称 RAW、完整图精密曝光或原片无法恢复。

### C. 导出结果

- [ ] 默认完整尺寸 JPEG95；>8192px源完整尺寸不被自定义上限截断；失败不自动降档。
- [ ] 分享长边≤2048、质量90、不放大；2048含框口径与相册实际像素相符。
- [ ] 自定义640／8192边界、小于640源、竖图／横图／全景、奇数尺寸、非法输入均符合规则。
- [ ] 同图有／无构图和边框，输出比例、方向、字样相对位置与完整成品一致。
- [ ] 质量70／90／95／100的输出均可完整解码；色彩sRGB、EXIF宽高／方向正确。
- [ ] 质量／实际尺寸不同不串缓存；档位名不同但实际规格相同能复用。
- [ ] 估算明确范围／未知／实际，不能把批量部分估算冒充总数；最终文件展示实际大小。
- [ ] 元数据白名单、GPS剔除、有理数快门、拍摄时间与“新副本本次时间”分别核对。
- [ ] 旧完整JPEG95结果及其相册回执升级后仍可识别；不重复保存、不按文件名猜身份。
- [ ] 相册已存在／被删／被改／断权、显式新副本、发布中断恢复分别验证，不多存一份。
- [ ] 原图SHA、原PNG、已有完整成品与草稿在导出和取消前后不变。
