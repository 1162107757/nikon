# 社区、下载与 App 更新

本说明保留 Android `0.10.1-beta` / versionCode `55` 与在线后台 `1.4.0` 的历史基线；最新 0.11.3（60）与后台 1.4.2 的变更见下面增量说明。原预设、相册、照片直播、Wi-Fi／USB 导入及其历史验证保留各自范围；社区与更新不要求用户先连接相机。

0.11.3：预设首页移除消息和文字发布入口，右下角悬浮加号随“我的／在线”切换为本地导入／发布。手机实际崩溃栈定位到已有草稿的 `Files.readString`，改为最多 32 KiB 的严格 UTF-8 流读取；缺失、已有草稿均可打开。未读提醒集中在设置标签圆点与消息行数字（99+ 封顶），前台每分钟及页面返回刷新；显示的消息页按 ID 批量写入已读，确认成功才消角标，未加载的新消息仍未读。切换账号隔离数量，角标更新不重建预设详情或照片主图。

010 增量迁移将每条评论改为服务端生成审核结论：正常评论直接可见，含疑似外链、广告引流、公开联系方式、辱骂或刷屏的内容进入既有人工队列并保留原因。客户端不能提交有效审核结论，缺失服务端结论默认人工；待审回复通过后才通知。当前是解释性规则筛查，不能覆盖所有变体或上下文，管理员需继续处理误判与举报。原注册验证码、频率和额度不变，历史幂等请求兼容，不因规则版本变化重复生成评论。

游客仍可使用既有预设、照片和相机功能；发布、评论、举报与个人消息需要普通用户登录。管理员登录与 App 普通用户会话独立。

0.10.2-beta（56）将讨论直接嵌入完整预设详情底部，保留效果主图、曲线及导入操作。评论加载、翻页、发送与回复只更新讨论区域，不重建整页；游客前往登录后返回原预设与草稿。消息中的回复入口打开同一完整详情并定位相关讨论。已从在线库下载的文件持久保存原在线预设 ID，本地重开仍使用原讨论；来源未知的本地文件不创建虚假评论区。

公网下载页允许游客访问。当前网址属于 CloudBase 测试域名，首次浏览器访问可能先看到平台访问确认；它不等于 App 登录。正式商业域名尚未配置，需使用用户自有域名后另行配置，不能将当前平台测试域名写成正式商业域名。

发布时填写名称、简介、分类及可选兼容机型，选择 NCP 与可选效果图，并明确确认拥有公开分享权利。编辑内容与所选文件保存在对应账号的本地草稿，远端保存及提交使用幂等请求标识；失败后显示原因，由用户手动重试。UI 在待审时锁定编辑，退回说明及审核结果保留到消息。保存草稿、提交审核、审核通过和下载到手机是不同结果。

审核通过后公开的是已审快照。已发布稿件后续修改不会直接替换公开内容，需再次审核；下架清除公开快照，并在每次社区文件读取时重查，因此旧社区文件地址也不能绕过撤回。未通过文件只能由作者或管理员的授权入口读取。NCP 上传上限 1 MiB，效果图上限 4 MiB；文件仍须通过实际格式校验，同一作者重复 NCP 内容会被拒绝。

评论仅支持最多 500 字纯文字，不支持 HTML 或链接。顶级评论与其回复为两级，回复入口继续指向顶级评论，不建立第三层；列表先显示部分回复，“查看更多回复”按页读取并去重。注册未满 24 小时且尚无可见评论的账号，其评论或回复先进入 `pending`，App 说明“评论已提交，审核后展示”；未获批内容不进入公开列表。作者删除已公开评论后保留“评论已删除”状态，删除从未公开的待审评论不泄漏公开占位或作者。管理员隐藏与作者删除分开。

可见回复其他用户的顶级评论时生成个人消息；待审回复在管理员通过后才在同一事务生成通知，重试／再次恢复不会重复通知，自回复不通知自己。投稿审核通过、退回及下架也生成持久通知。消息目标被隐藏、删除或下架时显示不可用，不再透露原正文。禁言只限制新增评论／回复，不影响读取消息或删除自己的内容；禁止投稿使用独立期限。

## 管理员操作

后台现有预设管理和用户管理保留，新增两项真实目的地。所有 `nikon_admins` 中合法且未停用的管理员都可管理版本，没有固定用户名授权规则。

社区管理的五个栏目如下：

- 投稿审核：按状态查看，核对最新修订、NCP、效果图和历史版本，再通过、退回修改或下架；处理说明进入作者消息，修订冲突需重新读取。
- 评论管理：按“待审核”等状态查看正文及作者，待审行使用“通过审核／不予展示”，分别调用 restore／hide 并明确确认；可见／隐藏评论提供隐藏／恢复，作者已删除的评论不能恢复。
- 举报处理：确认违规或忽略举报并记录说明。举报结案与隐藏评论为独立操作，需要隐藏时到评论管理执行。
- 风控规则：维护新用户／普通用户每日投稿、评论、上传及评论间隔等规则；新请求即时采用保存值。点击作者或输入用户 ID，设置禁言与禁止投稿截止时间，留空解除对应限制。
- 操作审计：查看操作者、目标、决定、说明及规则变更前后值；不在公开目录暴露管理日志。

App 版本流程为“上传并校验 → 草稿 → 复核并二次确认上架 → 必要时撤回”。上传时选择 `stable`／正式版或 `beta`／测试版，并填写更新说明。后台从 APK 读取真实包名、versionName、versionCode、minSdk、长度、SHA-256 和签名，校验包名 `com.nikonpreset.usbprobe` 及现有固定证书；当前服务支持完整 v2／v3 内容签名校验，拒绝未审定的签名轮换。证书固定值以 [APK 校验器](../online-library/server/apk.mjs) 为准，私钥不进入浏览器、数据库或部署包。

单 APK 不超过 4 MiB，以 512 KiB 分块上传。分块完成后重新读取并校验，再组合、检查和入库；上传成功只生成草稿。草稿可修改更新说明，上架后包、渠道及元数据不可覆盖，撤回不能重新发布。同渠道发布须高于该渠道曾发布版本的 versionCode，已撤回版本仍是版本上限的历史标记；不会通过撤回自动向用户提供旧版。上架／撤回及上传校验保留审计。

## 注册验证与运行额度

注册先 `GET /preset-library/auth/challenge?installationId=<UUID>` 获取 PNG 像素与 challenge ID。验证码两分钟有效，与来源及安装标识绑定；消费在数据库内锁定并标记一次性使用，错误、过期及重放要求刷新。PNG 不含答案文本／向量信息。图形识别仍可能被自动化，验证码只是分层限制的一部分，不能宣传为绝对阻刷或商业级机器人识别。

注册、挑战和社区写入的安装／来源／全局限额由 PostgreSQL 原子执行，服务多实例共享额度，不能靠重试跨实例绕过。来源使用 HMAC，不将原始 IP 写入风控键；IPv6 以 /64 归桶。用户已批准当前生产的 loopback 代理来源白名单及 `TRUSTED_PROXY_HOPS=4`，三类真实请求（含伪造 X-Forwarded-For）核对了稳定来源；代理链变化后应重新核对配置，不能直接信任任意请求头。

| 默认限制 | 当前值 |
| --- | --- |
| 注册，每 15 分钟 | 每安装 3 次、每来源 8 次、全局 120 次 |
| 注册未满 24 小时：提交／评论／上传 | 每 UTC 日 1／10／4 次 |
| 其他用户：提交／评论／上传 | 每 UTC 日 3／50／12 次 |
| 同时待审核稿件 | 每用户最多 3 份 |
| 连续评论间隔 | 每用户至少 30 秒 |
| 举报 | 每用户滚动 24 小时最多 10 次，同一评论去重 |
| 后台版本变更请求 | 全环境每 15 分钟 256 次，含空请求及冲突请求 |
| 后台版本实际存储写入 | 全环境每 UTC 日 64 MiB，分块与组合后完整 APK 均扣实际字节 |
| 公开版本元数据 | 每来源每分钟 120 次、全局每分钟 1,200 次 |
| 公开 APK 下载 | 每来源每小时 20 次／80 MiB、全局每日 1,000 次／2 GiB |

社区每日额度使用 UTC，不按手机时区；“新用户”为注册未满 24 小时。后台可配置社区用户额度，表中记录初始默认值；注册与版本服务硬限制以服务端和迁移源码为准。上传在读取／写入前预留额度，失败传输和冲突重试也可能消耗预算，达到限制需等待窗口恢复。

## 公网下载与 App 可选更新

下载页默认正式渠道；只有正式渠道从未发布时才可明确提示并展示测试版，撤回不会静默回退。页面展示实际版本、最低 Android、大小、更新说明、SHA-256、包名、证书指纹及下载页二维码。`/releases/latest` 按渠道、客户端 versionCode 和 SDK 返回是否可更新；`/releases/<id>/file` 每次重查发布状态，并在远端文件读取后再查，返回前核对文件长度与哈希。

下载页另展示三张真实原生界面的预览，图源为 `community-native/final/light/` 的 `preset-comments.png`、`submission-editor.png`、`messages.png`；它们属于 `ee597f…` 候选的 QA 截图，页面明确写明“测试版界面预览，截图内容为演示数据”。图内账号、评论及通知是合成演示，不是生产用户内容，不含私有数据或凭据，也不证明截图来自最终 55。桌面三列，手机可横向滚动，图片有替代文字与说明。

App 默认选择正式渠道，测试渠道由用户明确选择。应用空闲、当前网络已通过互联网验证且距上次检查至少八小时时，可做轻量自动检查并提示；用户仍须选择下载，没有强制更新。相机 Wi-Fi 没有互联网时说明等待可上网网络，不自动切换相机连接。计费网络下载先确认，系统 DownloadManager 承接可取消的下载，记录任务 ID 与元数据，进程重建后恢复查询；前台进度原位刷新，暂停时停止 UI 轮询。

下载完成后核对实际大小、SHA-256、包名、单签名证书与已安装应用一致、versionCode 必须更高、minSdk 与设备兼容；安装前再从服务器检查所选版本仍为当前已发布项。校验通过的 APK 复制到应用私有位置，通过只读内容 URI 交给系统安装程序。没有允许本应用安装时先说明并进入 Android 授权界面，返回后重新走安装准备。

安装前阻止直播、预设导入、连接准备、照片传输／保存／处理等任务。若仅保留空闲相机连接，必须由用户确认“断开并继续”，等待实际连接结束后才继续；安装前仍复查任务状态。Android 安装程序保留最终确认，取消不会替用户安装。管理员发布、客户端下载／校验和设备覆盖升级须分别验收。
