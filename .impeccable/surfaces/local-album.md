# Direction contract

MODE: Operate. 83 / 0.16.0-beta is a narrow, user-approved code-led extension of the incumbent native app. PRODUCT.md and DESIGN.md retain the cloud-white/graphite world. No new comp, identity, icon family or production raster is needed. Native Android dp/sp, Back, insets and control semantics apply; no HTML/CSS detector.

THESIS: Choose local photographs, refine them, and publish only the chosen versions.

OWN-WORLD: Existing UiPalette cloud-white/graphite, native sp labels and Canvas line icons. AppIcon's existing PLUS/MORE/ALBUM/CAMERA vocabulary and native Ripple feedback remain authoritative. Runtime photos are actual permitted originals/versions; screenshots and generated fixtures are QA only.

STORY: Browse phone or durable App photos, choose one or up to 100, use the existing editor/batch flow, then explicitly choose App-only or phone publication. Reuse a valid existing public version; request a new dated copy only when intended. Keep source photos and drafts.

FIRST VIEWPORT: Two sources, App 内 then 手机, with App 内 the initial source. Show actual access/scope status and date groups over a lazy grid. A single filled 56dp floating “＋” with content description “选择照片” is the add-photo action on either source. The 48dp native overflow anchor owns refresh, selection and relevant access actions. Former persistent toolbar/access rows are hidden. When phone access is absent, centered scrollable guidance shows “点击获取授权” plus the alternative of choosing specific photos with “＋”.

FORM: Native Java Views within the established application. Normal gallery uses three columns, noncompact width>=600dp uses five. Compact height means screenHeightDp<480 and width>height: MainActivity reduces root title to 20sp in a minimum 48dp row; source, scope, progress, status and overflow share one row. Grid columns derive from measured body width/height, font scale, navigation reserve and usable photo edge, not a fixed landscape count. Reserve the right-side FAB region and bottom navigation space. Full first-row thumbnails and filenames must be identifiable above navigation; denied heading, explanation and authorization stay accessible. Empty guidance scrolls. FAB is hidden while selecting/importing; selection count/cancel/batch actions appear then.

ROOT SEMANTICS: Visual navigation is 预设|同步|相册|设置. The old album root is renamed 同步 and keeps camera/live/downloaded/project history. New 相册 owns local browsing and a separate local-workspace AlbumPanel editor backed by shared controller/preset stores. Internal root IDs remain 1 sync / 2 settings / 3 local; visual order does not rewrite those IDs. Switching roots pauses local UI observation rather than closing the shared camera controller or stopping live acquisition. Existing conflict/queue rules remain.

ACCESS / PICKER: Entering 手机 alone does not request permission. API 34+ explicit access requests READ_MEDIA_IMAGES plus READ_MEDIA_VISUAL_USER_SELECTED; API 33 requests images, older versions external read. Partial access is stated and can be reselected; phone permissions can be managed in application settings. Resume rechecks access and invalidates old phone rows/thumbnails. Denial/revocation never blocks durable App photos. Floating “＋” calls ACTION_OPEN_DOCUMENT/CATEGORY_OPENABLE with image/* plus explicit JPEG/PNG MIME types and multiple selection. Cancellation imports nothing and preserves existing data. Missing system activity reports a recoverable message.

BROWSING: Phone pages contain at most 120 JPEG/PNG records, ordered by added time descending with ID tie-break; only currently accessible records can appear. App photos use existing original/effect grouping and photo dates. Sources retain independent scroll state. Thumbnails are sampled on demand with a bounded worker/cache; browsing never performs a full-library import. Selection is capped at 100; unavailable source, empty state, read error and partial preparation have explicit text and recovery.

IMPORT: Accept content URIs for real JPEG/PNG, checking metadata before/after, complete structure/image validity and repeated content hash. A JPEG working original preserves exact bytes. A PNG requires “以白底编辑 PNG” confirmation, keeps its original private bytes, and uses a white-flattened JPEG 95/sRGB working copy. Import identity combines URI hash and original-content hash; it does not merge arbitrary equal pixels across different URIs. Working originals live in private pictures/camera-album; PNG originals and versioned provenance live in local-photo-sources. These are formal private data, not preview cache and not automatic uploads. Limits are 96 MiB per photo, 50 million pixels, 1 GiB aggregate phone input plus memory checks. Failures never silently downsize. Cancel/partial failure may leave completed private copies but does not start editing a partial selection.

EDITOR: A verified complete private JPEG enables the incumbent photo-first editor: 13 manual values, preset/strength, composition, recipes, compare, 32-step session history and account/photo drafts. The confirmed PNG working JPEG follows this same boundary. Recipes preserve each target's geometry; batch snapshots preserve independent settings. Preview-only camera photos retain pure browsing. See photo-filter-editor.md for the existing direction, material and editing rules.

DESTINATION: PhotoSaveChoice presents “仅保存在 App 内” and “保存到手机相册” in a scrollable native dialog. Sync download/sync-effects/live initially default APP_ONLY; edited export initially defaults PHONE_ALBUM. Remember only accepted positive choices, per scene and per live project. Cancel does not commit preferences. Tasks/retries freeze target plus allowed extra-copy choice. Legacy external-write permission is needed only for phone publication on API <=28, never App-only. App-only writes formal private results/draft associations and adds zero public MediaStore rows.

REUSE / COPY: Phone publication reuses a still-effective same-version receipt only after current URI/content/pending/ownership checks. “另存新副本” is offered where allowed, starts unchecked, is enabled only for phone destination and is cleared by App-only. First new publication is dated now. If a valid same-version public copy already exists, explicit extra-copy is required to add another. New publication uses current save-time JPEG/MediaStore metadata on frozen staged bytes without pixel recompression; retry completes the same request. Old public copies, render-cache bytes and original bytes/time remain; successful publication updates local effect mtime. This replaces 81/82's every-explicit-export-new-copy default; historical docs retain their version scope.

FOREIGN ORIGIN: Unchanged imported JPEG can reuse its still-readable identical MediaStore original. LocalPhotoOrigin is read-only provenance, never owned publication or permission to delete the phone source. Missing/changed source may publish the durable private copy; unavailable verification blocks silent duplicate publication and offers reauthorization/reselection or explicit extra copy. A PNG working JPEG is a separate new version. Configured Android private-root aliases /data/user/0 and /data/data are accepted while traversal, child symlink, outside-root and ownership guards remain. Stale owned-publication receipts are handled under existing exact-byte/ownership guards; uncertainty does not grant deletion authority.
